# Security hardening pass — 11 September 2026

This pass follows the local security review of commit `2b3c001`. It implements bounded protections for the existing offline application. It does not add a cloud service or migrate the live database to an encrypted vault.

## Changes mapped to the report

| Finding | Delivered behavior | Remaining limit |
| --- | --- | --- |
| S01 recovery export | Startup errors and blocked second tabs no longer offer plaintext download. Original storage is preserved. | Corrupt anonymous data requires an existing backup or controlled owner-assisted profile recovery; there is no in-app raw recovery bypass. |
| S02 sessions/storage | Authentication is held in memory, verified again on page load, expires after eight hours, and checks the current password hash. | Browser storage remains plaintext; no trusted backend or adversarial staff isolation. |
| S03 retained copies | Migration verifies its destination and removes migrated local data/recovery/queue copies. Account deletion removes known account snapshots and a tracked anonymous copy. Failures are surfaced and leave the login available to retry. | Unlabelled copies created by older versions cannot be safely assigned to an account automatically. Downloaded/device backups cannot be erased by the app. |
| S04 permissions | Missing/inactive staff denied, no first-owner fallback, centralized locked-state checks, stale-context rejection, pending modal cancellation. Cashiers cannot change costs, view dashboard/reports, choose stores or export cost-bearing inventory. | All controls execute on a trusted client. Discount/credit supervisor policies remain a product decision. |
| S05 store ownership | Selectors require an exact store. Missing store IDs migrate only when there is exactly one store; ambiguous or conflicting references are rejected. | There is no backend tenant enforcement. |
| S06 imports | File, text, node, nesting, collection and CSV field/row bounds run before expensive processing/mutation. Unknown top-level database fields are rejected. | This is not a complete allowlist of every nested extension field; bounded unknown nested fields remain compatible. Phone-scale load/performance testing remains pending. |
| S07 credentials | Twelve-character minimum for new passwords, 256-character maximum; progressive login/PIN delays; PBKDF2-SHA256 600,000 iterations with legacy parameter migration; password change signs out. Five-minute idle and hidden-page locking for protected counters. Fresh owner verification on staff, backup and sensitive settings flows. | Local throttling can be reset by a storage-controlling attacker. No hardware-backed keys or offline guessing prevention. Low-cost phone KDF performance still needs device testing. |
| S08 browser policies | CSP, framing denial, nosniff, referrer and permissions policies on the local server, plus Vercel/Netlify configuration and production HSTS. Inline script handler removed. | Inline styles remain allowed; Trusted Types not enabled. Actual deployed hosting headers and all target-device integrations need release verification. |
| S09 backup integrity | New exports use AES-256-GCM and a separate passphrase-derived key with random salt/IV; reusable PINs omitted. Legacy plaintext imports remain supported. Restore keeps current staff, PINs and UPI destination, previews this behavior and asks for owner verification. | Passwords cannot be recovered. Authentic old backups can roll back books. New-device staff/payment settings must be configured deliberately; imported historical staff IDs may not have a current name. |
| S10 media/privacy | Shared speech consent explains possible provider processing. Voice callbacks check account/store/staff context; lock/context changes abort recognition and speech output. Camera permission completion and detector results reject stale context; modal close stops tracks. | No local-only speech guarantee or real microphone/camera test in this pass. |
| S11 releases | Public asset allowlist, `dist` build, content-derived service-worker cache version, scope-specific cache cleanup, waiting update notification, no forced mid-session activation, CI checks, backup ignore patterns and security reporting policy. | Dedicated origin required: namespacing is not isolation. Old unscoped caches are preserved to avoid deleting another installation's cache. GitHub branch protections/private reporting settings were not changed. |
| S12 accountability | Backup/restore/export events recorded; policy explains 800-entry local retention and trust limits. | No append-only server audit trail, verified payment integration or forensic guarantee. |

## Verification

**36/36 tests passed**: the previous 23 tests plus 13 targeted security cases for the actual application modules. Synthetic storage only; no real shop data is changed by the tests. Coverage includes blocked-tab recovery, fresh and expired sessions, migration/deletion failures, permissions and lock transitions, malformed imports, legacy password upgrades and throttling, encrypted backup round-trip/tamper rejection, protected restore settings, speech cancellation, real HTTP response headers and public release contents.

Browser checks used a local development server and existing synthetic audit data. Verified shell/settings rendering with the CSP, the owner-verification prompt before backup export, cancellation, and a real second tab displaying only retry guidance without a recovery download. Browser console showed no errors during these checks. Credential creation/change, encrypted file upload/download, actual camera/microphone capture and an installed-PWA upgrade were not exercised end-to-end in a browser; crypto/auth flows are covered by the module tests.

Before production use, verify policies on the deployed origin, close/reopen an installed PWA to apply the update, and test backup recovery and camera/voice on a supported inexpensive Android phone. Keep a recoverable copy of the existing browser profile before upgrading real records. No deployment or merge is part of this pass.
