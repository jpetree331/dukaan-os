# Stock counts, disposal and reversal

Owners can count a selected batch, dispose of expired or damaged goods, or add a found-stock batch. Every change records actor/store, reason and note, signed quantity, original batch cost/provenance, prior/new batch count, prior/new physical stock classes and a command ID. A modal captures the opening stock fingerprint and refuses a stale count if intervening activity changed stock. Same-ID/same-request retries do not repeat effects.

Physical stock is partitioned into sellable, quarantined, and expired non-quarantined goods. An expired quarantined unit is counted only in quarantine. Existing checkout already excludes both expired and quarantined goods. Counting an existing batch preserves its cost, expiry, quarantine status and purchase attribution. Newly found goods can be given an explicit unit cost, expiry and quarantine status. An expired disposal requires an expiry before the current local date. Count zero means none remain; it never means delete transaction history.

Reversal appends an equal-and-opposite linked adjustment, retaining batch identity and classification. Each movement can be reversed once. A reversal that removes stock refuses when those units have since been consumed. A later separate count is the reconciliation route; restoring an old database is not. Reversing a disposal restores the original quarantine/expiry condition and does not make unusable stock sellable. Reversing a reversal is allowed through a new link, with the same stock-availability rules.

The inventory editor no longer silently changes existing stock. New-item opening quantities remain supported. CSV updates of undated, unbatched existing stock retain their original behavior but append a disclosed “Owner CSV stock count” movement in the same atomic save; failed rows preserve both stock and adjustment history. CSV cannot replace batch quantities. Existing restocks, purchases and sale/return movements retain their own histories; this screen is an adjustment log, not a reconstruction of all historical inventory movements.

History displays the latest 50 adjustments with signed cost values and exports every adjustment as CSV. Values are informational stock-cost changes. No cash, supplier/customer debt, sales revenue, sales cost or expense classification is automatically changed by a count or disposal. New optional stockAdjustments records reject older strict readers and are included in encrypted snapshots, migration and journal replay. Preserve a compatible backup before any data-format rollback; Git rewind is only a code checkpoint.
